# build-base

One nixpkgs, one Rust toolchain and one set of crate overrides, taken by every
repository as its `base` input, so a crate at one version and feature set has
one store path everywhere and the remote builder's store serves it to all.

A Cargo workspace commits a `Cargo.nix` generated by this base's crate2nix
(`nix run github:LiGoldragon/build-base#crate2nix -- generate`) and its flake is:

```nix
{
  inputs.base.url = "github:LiGoldragon/build-base";
  outputs = { self, base }: base.lib.workspaceOutputs { cargoNix = ./Cargo.nix; };
}
```

That gives one derivation per crate, third-party and member alike, and per
member: `packages.<member>`, its build; `checks.<member>`, which runs the test
binaries its test build compiled and compiles nothing. A test build honours
the member's `[[test]]` targets as cargo does: a target whose
`required-features` the feature set lacks is left out, and a target with
`harness = false` is compiled as a plain binary whose own `main` the check
runs. `checks.cargo-nix`
proves the committed `Cargo.nix` is what this base's crate2nix generates from
the workspace: it compares Cargo.lock's packages with the crates Cargo.nix
records, then runs `crate2nix generate` offline in the sandbox over the source
with those crates vendored, each git source apart by its url and commit, so two
git sources of one crate name and version both resolve, and diffs the result
with the committed file.
Commit `crate-hashes.json` with `Cargo.nix`: the offline generation reads git
dependencies' hashes from it.

The base holds one version set for every third-party crate (a locked package
from a registry) across the active repositories, `third-party-versions.json`:
crate name to the versions locked, one per crate except where the locks carry
semver-incompatible versions side by side. `checks.third-party-versions`
refuses a Cargo.lock that locks a third-party crate at a version outside the
set, naming each as `<crate>: lock <version> set <versions>`. A version moves
once, here, and every active repository's lock moves with it. The set is
derived, never written by hand:

```sh
nix run github:LiGoldragon/build-base#third-party-version-set -- <Cargo.lock ...>
```

writes `third-party-versions.json` in the working directory from the given
locks, or, where two locks carry semver-compatible versions of one crate that
differ, names the crate, each version and its lock, and writes nothing.

`memberChecks` and `extraChecks` are functions of the build context (below)
with `workspace`, the imported Cargo.nix, `tests`, each member's test build,
`check`, the base's check of a member under a feature set
(`check "member" [ "default" "feature" ]`), and `doc`, rustdoc over a member's
library under a feature set with rustdoc flags, its dependencies linked as its
build links them, no cargo involved
(`doc "member" [ "default" ] [ "-D" "warnings" ]`, the documentation in
`$out/share/doc`), and `clippy`, clippy-driver over every target of a member
under a feature set, as `cargo clippy --all-targets` lints them: the member's
test build compiled by clippy-driver over the dependencies that build already
links, the member's `[lints]` (or the workspace's, where it takes them)
applied uncapped and the given flags after them, no cargo involved and
nothing but the member compiled
(`clippy "member" [ "default" ] [ "-D" "warnings" ]`). `memberChecks` gives, by member name, the check that stands in place of
the base's (a member whose tests need an environment), or null for a member
that has no check. `extraChecks` returns the repository's own further checks,
under names no member, `cargo-nix`, `third-party-versions` or `default` has:

```nix
base.lib.workspaceOutputs {
  cargoNix = ./Cargo.nix;
  memberChecks = { pkgs, tests, ... }: { frozen-contract = null; };
  extraChecks = { pkgs, toolchain, workspace, tests, doc, clippy, ... }: {
    fmt = …;
    doc = doc "member" [ "default" ] [ "-D" "warnings" ];
    clippy = clippy "member" [ "default" ] [ "-D" "warnings" ];
  };
}
```

`packages.default` is every member and `checks.default` every check, the
repository's own included, so a green default is the whole gate.

A Cargo.nix kept apart from the workspace it was generated from (a pinned
dependency built per crate) takes the same freshness check from the context:

```nix
cargoNixCheck {
  source = <the workspace, holding Cargo.toml and Cargo.lock>;
  cargoNix = ./nix/dependency/Cargo.nix;
  crateHashes = ./nix/dependency/crate-hashes.json;
}
```

`lib.contexts.<system>` holds `pkgs`, `toolchain`, `crateOverrides`,
`crate2nix`, `buildRustCrateForPkgs` and `cargoNixCheck` for a flake that needs
more, and `lib.workspace.<system>`, given the same arguments as
`workspaceOutputs`, is one system's workspace, `packages`, `tests`, `checks`
and `devShell`, for a flake that composes its own outputs. Cargo stays the
local loop: `nix develop`.
